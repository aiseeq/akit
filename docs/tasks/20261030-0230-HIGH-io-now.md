# pressure: моментальный диск из источника состояния вместо avg60

Статус: готово
Исполнитель: akit-master

## Вход
- Правило допуска от aguard-master 30.10 ~02:25 CET (письмо в сессию akit-master); калибровка 29.10 20:49 … 30.10 02:25: перед всеми 11 фризами от 1 с io_full за 5 с ≥ 484 мс; avg60 опоздал на 2–15 с в 5 из 11, в 22:00 не сработал; окно 5 с держит 8,3 % секунд (эпизоды p50 5 с, p90 15 с), avg60 — 5,5 %, но p90 557 с.
- Решение пользователя `instant-not-average` (~/.claude/decisions.md): моментальное значение, среднее — вспомогательное.
- Форма согласована с aguard-master 29.10 (6 поправок): Rule — чистая функция; клиент в Meter; срок 200 мс; сентинел в Skipped вместо лога; откат — дельта `total` full за окно свопа; kind — аргумент Check, не Limits; один запрос now+profile; «на PC» решает вызывающий.
- Источник — закрытый проект: в коде, тестах, README и коммитах akit его имени нет; контракт нейтральный «источник моментального состояния диска», описан в akit.
- Живой сокет на машине: `$XDG_RUNTIME_DIR/io-state.sock`, ответ проверен 02:28 CET.

## Что сделать
Контракт (описать в README akit, раздел busy → «Disk state source»):
- Unix-сокет, путь `$XDG_RUNTIME_DIR/io-state.sock`; нет XDG_RUNTIME_DIR — источника нет. Одно соединение — строка JSON запроса, строка JSON ответа.
- Запрос `{"v":1,"q":"now","kind":"<вид>"}` (kind пусто — поле не слать). Ответ: `v` (1), `error` (строка при ошибке), `at` (RFC3339Nano), окна `"1s"`, `"5s"`, `"30s"`: `{steps, io_full_ms, stall_ms, write_bps, read_bps, w_await_ms, inflight_max, cpu_some_ms, runnable_max}`; `nproc`; `open`: `{"open":bool,"ms":N}`; `profile` — свод профиля вида, любое JSON, клиент его не разбирает, отдаёт как есть. Лишние поля игнорируются.

pressure:
- `ErrNoIOSource` (нет XDG_RUNTIME_DIR, нет файла сокета, ECONNREFUSED) и `ErrIOSourceFailed` (срок 200 мс на соединение и ответ вышел, кривой JSON, `v` ≠ 1, непустой `error`, `at` старше 2 с от now Meter) — сентинелы в `Verdict.Skipped`; подробность сбоя — `Load.DiskFault error` (обёрнутая), чтобы потребитель мог её записать.
- `DiskNow` (снимок источника: At, окна 1s/5s/30s, NProc, Open, OpenMs, Profile json.RawMessage) — в `Load.Disk *DiskNow`, nil без источника.
- `Load.IOFull` — % окна `Load.IOWindow`, когда все задачи ждали диск, округлён до 0,1: при источнике — `io_full_ms` окна 5s / 5000 мс; без источника — дельта поля `total` строки full `/proc/pressure/io` (мкс) за то же окно, что и своп (fresh — SwapWindow, иначе с прошлого Check), / прошедшее время. Округление: `math.Round(x*10)/10` от процента, чтобы 480 мс из 5 с давали ровно 9.6.
- Rule, мера IO (место в порядке прежнее: после CPU): `Limits.MaxIOFull ≥ 100` — диск не судится вовсе (так в graft выключают дисковый гейт); иначе занята, если `Disk != nil && Disk.Open` (Why: «disk freeze in progress for N ms») или `IOFull >= MaxIOFull` (было `>`; Why: «IO pressure X% of the last 5s is at or above L%», окно из IOWindow). avg60 из правила уходит.
- `DefaultLimits.MaxIOFull` = 9.6 (480 мс из 5 с); комментарии Limits/Load/DefaultLimits — новый смысл.
- Подпись: `(*Meter).Check(ctx, l Limits, kind string, fresh bool)`; пакетная `Check(ctx, procRoot, l, kind)`. Запрос к источнику — в конце Check, после окна свопа (самый свежий). Тесты Meter: поле пути сокета (неэкспортируемое) и now.
- cmd/busy: флаг `--kind K` (передаётся в запрос); `--io-full P` (порог, по умолчанию 9.6); в строке — `IO pressure X% of 5s from the disk state source (limit L%)` или `... of 1s, /proc/pressure/io total (limit L%)`, при Open — `disk freeze for N ms`; Skipped как и сейчас («not checked: …» — для ErrNoIOSource/ErrIOSourceFailed писать «no disk state source, /proc/pressure/io total used» и причину из DiskFault). README busy — новый смысл порога.
