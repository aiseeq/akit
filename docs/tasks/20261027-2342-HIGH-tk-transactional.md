# tk: тикеты вне репо, note, ls --by, ждёт к сроку

Статус: готово
Исполнитель: luna:1027-2312-tk

## Вход
- Проблема: тикет — транзакция работы (намерение → исполнение → проверка, прерванное продолжается по тикету; правило dev-process «Учёт задач»). Лид, админы и прогоны Сна и Дайджеста ведут тикеты в `docs/tasks/` своей папки (`~/docs/tasks`, `~/work/docs/tasks`, `~/git/docs/tasks`); `~` — рабочее дерево с отдельным git-dir, `~/work` и `~/git` — не репо: `tk new` там падает «repository root: exit status 128». Шаг с побочным эффектом пишется в журнал правкой файла — нет команды.
- Метод: доработка `cmd/tk` поверх пилотных правок (тикет tk-pilot-fixes), тем же бойцом в том же дереве.
- Дешевле: нет — правка файлов руками в каждой сессии дороже и с ошибками формата.
- Инструмент: `tk` (akit).
- Цена: один заход бойца Luna.
- Если не делать: после рестарта и сжатия сессии продолжают по пересказу в файле возобновления, а не по тикету.

## Что сделать
1. Вне git-репо (или `git rev-parse` падает): база — ближайшая папка с `docs/tasks/`, от текущей вверх до `$HOME` включительно; не нашлась — `new` создаёт `docs/tasks/` в текущей папке, остальные команды — код 1 «no docs/tasks here or above up to $HOME». В репо — как сейчас (корень репо). Архив — `docs/tasks-archive/` той же базы. Флага `--dir` не нужно.
2. `tk ls --root DIR` с базой DIR (`~/git`: `~/git/docs/tasks` и проекты) — как сейчас; проверить на папке не-репо.
3. `tk note <id> '<текст>' [--by кто]` — строка в «## Журнал» (`- YYYY-MM-DD HH:MM note — кто: текст`), статус не меняется; пустой текст — код 2.
4. `tk ls --by <кто>` — незакрытые тикеты, где `Исполнитель:` равен кто (без учёта регистра) или, если исполнителя нет, первая строка журнала («открыт — кто»).
5. `tk ls --due` — только «ждёт» со сроком, который разбирается как время и уже наступил (по ним админ раздаёт ожидания в начале дня).
6. `tk ls`: у тикета с пустым разделом «Приёмка» (или «Чем проверить» у старых) — пометка `no-check` в строке.
7. `tk ls --json` (и с `--root`, `--all`, `--status`, `--by`, `--due`): массив объектов `repo` (при `--root`), `slug`, `status`, `prio`, `title`, `created` (из имени, RFC 3339), `changed` (последняя строка журнала, нет — mtime), `path`, `executor`, `waits` (текст `Ждёт:`), `overdue`, `no_check`. Пусто — `[]`.
8. `tk show <id> --json`: поля ls плюс `check` (текст проверки строки «готово» журнала), `checker` (кто в ней), `journal` (строки журнала).
9. `tk lint [--root DIR]`: строка на нарушение `<путь>: <что>`, код 1 при нарушениях, иначе `ok` и код 0. Нарушения: имя файла не по шаблону; статус не из списка; в тикете со строкой `Статус:` нет раздела «Приёмка» или «Чем проверить» или нет «Журнал»; «готово» без строки журнала «готово — кто: проверка»; проверяющий в ней равен исполнителю (без учёта регистра). Старые тикеты без строки `Статус:` — только имя и (если есть) статус.
