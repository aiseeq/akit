# shellcmd: дописанный ограничитель heredoc не попадает в аргументы

Статус: в работе
Исполнитель: akit-master

## Вход
- Остаток проверки calls-no-panic (30.10): команда кончается на `\` с незакрытым heredoc — ограничитель, дописанный parseShell, склеивается продолжением строки и попадает в Args: `pgrep a <<E \` → Args [a E]; `cat <<E; pgrep z \` → у pgrep [z E]. До v1.13.3 там была паника.

## Что сделать
- parseShell: перед дописанным ограничителем закрыть продолжение строки (нечётное число `\` в конце текста) лишним переводом строки.

## Приёмка
- Чем проверить: тест — `pgrep a <<E \` → pgrep [a]; `cat <<E; pgrep z \` → pgrep [z]; `echo a\\\\ <<E` (чётные `\`) без изменений; go test ./shellcmd/ ./transcript/...; glint 0; fuzz 2 мин без находок; корпуса без изменений.
