# user-word --brief: верный номер битой строки в предупреждении

Статус: открыт

## Что сделать
Находка проверки 7 тикета brief-user-words: в `user-word --brief` предупреждение `skipped N malformed transcript lines (line K: …)` называет не ту строку. В синтетике `line 10` при битой 11-й строке, первая форма (`user-word TRANSCRIPT 'FRAGMENT'`) пишет верно `line 11`.

Причины (cmd/user-word/words.go, scanChronologicalBriefLines):
- `lineNo` растёт только на записях, которые вернул readBriefRecord; пропущенные им записи с результатами инструментов не считаются;
- большой файл (> 256 КиБ) читается с середины (transcriptOffset), номер считается от точки seek.

Что сделать: номер в предупреждении `--brief` — номер строки файла, как у первой формы, или вместо номера то, что однозначно ведёт к строке (смещение в байтах, время записи). Имя файла — в предупреждении.

Чем проверить: тест на транскрипте с результатами инструментов перед битой строкой и на файле > 256 КиБ — номер (или указатель) совпадает с `sed -n` по файлу.
