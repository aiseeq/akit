# tk: находки пилота на двух репозиториях (7 пунктов) и шаблон тикета по общему решению

Статус: в работе

## Постановка
Пилот tk v1.1.0 на двух репозиториях дал 7 находок; шаблон и архив сводятся к общему образцу тикетов (раздел «Вход» с полями, «Приёмка», архив `docs/tasks-archive/`, журнал). Код — `cmd/tk/main.go`, тесты — `cmd/tk/main_test.go`, раздел `## tk` README.

## Что сделать
1. id в командах — slug, имя файла или имя файла без `.md`. Кривой id — код 2 с текстом «ID is the ticket slug (e.g. graft-hooks) or its file name».
2. Usage перечисляет все команды с их флагами (`--prio --title --by --all --status --root --note --check --doer --why --until --older`) и что каждый значит; `tk <команда> -h` печатает его же.
3. `tk show <id>` — путь первой строкой, затем весь текст тикета.
4. Статус «ждёт»: `tk wait <id> --until '<срок или условие>' [--by]` (без `--until` — код 2) ставит `Статус: ждёт` и строку `Ждёт: <…>` сразу под статусом (повторный wait заменяет строку, не добавляет вторую), строка журнала. `start` снимает строку `Ждёт:`. «ждёт» — незакрытый: `tk ls` по умолчанию его показывает, в строке — текст ожидания (`[до 2026-10-28 09:00]`); срок, который разбирается как время (пакет `timearg` akit) и уже прошёл, — с пометкой `overdue`.
5. `--by` и `--doer` — имя без пробелов (`^[\p{L}\p{N}][\p{L}\p{N}._:@-]*$`: сессия, id бойца), иначе код 2 с подсказкой. Исполнитель и проверяющий сравниваются без учёта регистра. Строка `Исполнитель:` в тикете не по этому правилу (свободный текст старых тикетов) при `done` — код 1 с подсказкой `--doer NAME`.
6. `tk ls --root DIR` не считает связанные worktree: папка, где `.git` — файл, пропускается (и DIR, и подпапки).
7. Шаблон `tk new`:
   ```
   # <заголовок>

   Статус: открыт

   ## Вход
   - Проблема:
   - Метод:
   - Дешевле:
   - Инструмент:
   - Цена:
   - Если не делать:

   ## Что сделать

   ## Приёмка

   ## Журнал
   - <время> открыт — <кто>
   ```
   Поля «Входа» — общие из образца: проблема ли это и где видно; достижима ли цель выбранным методом; нет ли пути дешевле; не баг ли это инструмента; стоит ли это ресурсов против очереди; что будет, если не делать. Их смысл — одной строкой на поле в README.
8. Архив — `docs/tasks-archive/` (не `docs/tasks/archive/`).
9. Слово приоритета в имени при чтении — любое `[A-Z]+` (в образце есть INFO, MED, EPIC, DONE); `new` принимает только HIGH, MEDIUM, LOW. Файлы `*.md` в `docs/tasks`, чьё имя не по шаблону `YYYYMMDD-HHMM-PRIO-slug.md`, `tk ls` называет последней строкой (`skipped N files not named …: a.md, b.md`), а не пропускает молча.
10. Текст разделов при создании: `tk new <slug> … --text FILE` (`-` — stdin, например heredoc): блоки `## <раздел>` из текста заполняют одноимённые разделы шаблона (Вход, Что сделать, Приёмка), остальные блоки встают перед «Журналом»; текст до первого `## ` — в начало «Входа». Без `--text` stdin не читается.
11. Ожидание внешнего действия, не срока (ждём ответа автора) — тот же `tk wait --until '<условие>'`: текст условия свободный; пометка `overdue` — только у сроков, которые разбираются как время.
